# Role: family_trees

## Purpose

This role generates and deploys static family tree websites. For each entry in the `family_trees` list, it:

1. Creates a directory under `/opt/<family_name>/` on the target host.
2. Copies and synchronises the family tree HTML file (pre-generated by genealogy software) from the Ansible control machine.
3. Post-processes the HTML to: strip inline `<style>` blocks (replaced by an external CSS), inject a responsive viewport meta tag and CSS link, add a Cyrillic-to-Latin transliteration script and toggle button, and rename the file to `index.html`.
4. Generates a `dictionary.json` file used by the transliteration JavaScript.
5. Deploys an nginx container that serves the static files.

This allows family tree HTML exports (which are typically self-contained and monolithic) to be served as lightweight, responsive web applications with language-switching functionality.

## Prerequisites

- `common`, `traefik` roles must have run.
- The family tree HTML files must exist at `<source_directory>/<family_name>/<family_name>.html` on the control machine.
- CSS and JavaScript files for the web UI (styles.css, cyr_to_lat.js) must exist in the role directory.
- Variables: `family_trees` list, `source_directory`, `user.*`, `dictionary`.

## Manual Execution Guide

### Overview

1. Create the directory on the target host.
2. Copy the HTML file.
3. Sync all supporting files from the role directory.
4. Post-process the HTML (strip styles, inject viewport/CSS, add transliteration).
5. Generate `dictionary.json`.
6. Rename to `index.html`.
7. Start the nginx container.

---

### Step-by-Step Instructions

#### Step 1: Create directories and sync files

```bash
# On the target host
sudo mkdir -p /opt/<family-name>
sudo chown <username>:docker /opt/<family-name>
sudo chmod 0755 /opt/<family-name>

# On the control machine — copy the HTML file
scp "/path/to/<family-name>/<family-name>.html" <username>@<host>:/opt/<family-name>/<family-name>.html

# Sync all supporting files (CSS, JS, images) from source
rsync -av "/path/to/<family-name>/" <username>@<host>:/opt/<family-name>/

# Sync role support files (styles.css, cyr_to_lat.js, dictionary.json)
rsync -av "update/roles/family_trees/files/" <username>@<host>:/opt/<family-name>/
```

---

#### Step 2: Post-process the HTML file (on the target host)

```bash
HTML="/opt/<family-name>/<family-name>.html"

# Strip inline <style> blocks
sudo sed -i 's/<style[^>]*>.*<\/style>//g' "$HTML"

# Inject viewport meta tag and external CSS link after the X-UA-Compatible meta tag
sudo sed -i '/<meta http-equiv="X-UA-Compatible" content="IE=9">/a <meta name="viewport" content="width=device-width, initial-scale=1.0">\n<link rel="stylesheet" href="styles.css">' "$HTML"

# Inject transliteration script and toggle button after </script>
sudo sed -i 's|</script>|</script>\n<script>var reset = 0;</script>\n<script src="cyr_to_lat.js"></script>\n<button class="button-round" onclick="toggleCyrLat()"><b>Sr/En</b></button>|' "$HTML"

# Rename to index.html
sudo mv "$HTML" /opt/<family-name>/index.html
```

---

#### Step 3: Generate dictionary.json

The `dictionary.json` file maps Cyrillic names to their Latin equivalents. It is generated from the `dictionary` variable in `host_vars/primary_server.yml`.

Create `/opt/<family-name>/dictionary.json`:

```json
{
  "КириличноИме": "LatinName",
  ...
}
```

(See the full dictionary in `update/inventories/production/host_vars/primary_server.yml`.)

---

#### Step 4: Start the nginx container

```bash
sudo docker run -d \
  --name <family-name> \
  --restart unless-stopped \
  --network proxy \
  --ip <docker-ip> \
  -e TZ=Europe/Belgrade \
  -v /opt/<family-name>:/usr/share/nginx/html:ro \
  --label traefik.enable=true \
  --label "traefik.http.routers.<family-name>.entrypoints=https" \
  --label "traefik.http.routers.<family-name>.rule=Host(\`tree-<family-name>.your-domain.com\`)" \
  --label "traefik.http.routers.<family-name>.tls=true" \
  --label "traefik.http.services.<family-name>.loadbalancer.server.port=80" \
  nginx:latest
```

Repeat for each family in the `family_trees` list, incrementing the Docker IP as configured in `host_vars/primary_server.yml`.

## Configuration Reference

### Variables

| Variable | Example | Description |
|----------|---------|-------------|
| `family_trees` | list | List of family tree definitions |
| `source_directory` | `/root` | Base path on control machine where family HTML files are stored |
| `dictionary` | dict | Cyrillic-to-Latin name mappings for `dictionary.json` |

**`family_trees` list structure** (from `host_vars/primary_server.yml`):

```yaml
family_trees:
  - name: "<family-name-1>"
    container_name: "<family-name-1>"
    volume: "/opt/<family-name-1>"
    host_domain: "Host(`tree-<family-name-1>.your-domain.com`)"
    static: "<docker-ip>"
  - name: "<family-name-2>"
    container_name: "<family-name-2>"
    volume: "/opt/<family-name-2>"
    host_domain: "Host(`tree-<family-name-2>.your-domain2.com`)"
    static: "<docker-ip>"
```

## Verification

```bash
sudo docker ps | grep <family-name>
curl -sk https://tree-<family-name>.your-domain.com/ | head -5
```

---

## Rollback / Uninstall

```bash
sudo docker stop <family-name-1> <family-name-2>
sudo docker rm <family-name-1> <family-name-2>
sudo rm -rf /opt/<family-name-1> /opt/<family-name-2>
```
